Aegify imports external analysis and runtime observations into one bounded
evidence contract. Imported data never becomes a native finding or reachability
edge without retaining its producer, artifact digest, repository, module, file,
and fidelity.

## Supported inputs

| Source | Input | Primary use |
|---|---|---|
| SARIF / CodeQL | SARIF 2.1.0 | Findings, locations, code flows and tool metadata |
| Semgrep | Semgrep JSON | Pattern findings and metavariable context |
| Joern | JSONL or GraphSON | Bounded graph nodes and edges |
| SCIP | SCIP index | Exact definitions, references, packages and external symbols |
| HTTP runner | Aegify evidence v1 | Request/response status and content digests |
| Browser runner | HAR plus browser evidence | Frontend requests observed during approved navigation/clicks |
| Proxy runner | Proxy evidence v1 | Redacted request mutations and backend observations |
| OpenTelemetry | Trace JSON | Parent/child runtime service and endpoint observations |

## Provenance contract

Each normalized record includes the fields that apply to its source:

```json
{
  "contract_version": 1,
  "producer": "external.sarif",
  "artifact_sha256": "sha256:...",
  "workspace_snapshot": "sha256:...",
  "repository_id": "orders-api",
  "module_path": "api",
  "file_path": "src/main/kotlin/OrderController.kt",
  "evidence_id": "ev:...",
  "fidelity": "compiler-exact"
}
```

Paths are repository-relative and validated before import. Workspace and artifact
digests make evidence reproducible and prevent records from silently attaching
to a different code snapshot.

## Safety bounds

- Reject absolute paths, traversal, symlink escape, and invalid archive members.
- Limit artifact size, result count, path length, graph node/edge count, and
  decompression ratio.
- Parse untrusted formats without executing embedded code or commands.
- Preserve unknown or ambiguous relations as counters, not guessed graph edges.
- Redact authorization headers, cookies, tokens, and configured sensitive names.
- Store hashes for sensitive query/body values where correlation is sufficient.

## Fidelity

Adapters assign evidence fidelity rather than treating every edge equally:

- `compiler-exact`: SCIP or compiler/classpath evidence identifies an exact target.
- `artifact-exact`: a pinned artifact and module identify a unique provider.
- `static-modeled`: Aegify framework or source analysis derived the relation.
- `runtime-observed`: an approved runtime trace or request observed the relation.
- `declared-fallback`: a manifest relation permits a conservative candidate edge.

Consumers should prefer higher-fidelity paths and display the chosen evidence.

## Runtime correlation

Runtime observations are normalized to method, path template, host/service,
status, trace parent, and redacted request evidence. Correlation proceeds from
exact route/template matches to normalized path matches. Public Gateway paths
are transformed before matching backend endpoints. Ambiguous matches remain
multiple candidates with confidence rather than becoming one arbitrary target.

## Evidence-state boundary

- Imported static result: `candidate`.
- Static or compiler graph path: `reachable`.
- Approved request or trace: `observed`.
- Separately authorized impact demonstration: `impact_proven`.

An adapter cannot promote a record to `impact_proven` by itself.

## Typical commands

```bash
aegify import-sarif results.sarif --repository orders-api
aegify import-semgrep semgrep.json --repository web
aegify import-joern graph.jsonl --repository payments
aegify import-runtime http-evidence.json --workspace aegify-workspace.yml
```

Use `aegify --help` for the current command and option set. Production pipelines
should pin the Aegify version and persist artifact hashes with the imported output.
