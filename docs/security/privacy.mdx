Aegify analyzes source code and may process security findings, dependency
metadata, runtime observations, and optional LLM context. Operators control where
the platform runs and which integrations are enabled.

## Data categories

- Source code, manifests, generated indexes, and compiler metadata.
- Findings, graph paths, endpoints, route mappings, and remediation notes.
- Runtime request metadata, trace identifiers, statuses, and content hashes.
- User, project, and scan metadata stored by the dashboard.
- Optional prompts and responses sent to a configured LLM provider.

## Default processing

The scanner runs locally and does not require an LLM. Dashboard data remains in
the configured database. Aegify does not include product telemetry. The dashboard
and Docker build set `NEXT_TELEMETRY_DISABLED=1`.

External transmission occurs only when an operator enables an integration such
as an LLM provider, DefectDojo, GitHub reporting, object storage, or another
configured service. Review that provider's terms and retention policy.

## Data minimization

- Runtime evidence drops authorization headers and cookies by default.
- Sensitive query and body values are replaced with SHA-256 digests when values
  are unnecessary for correlation.
- Browser and proxy runners restrict destinations and actions through policy.
- Imported evidence is bounded by size and count.
- LLM context should contain only the minimum relevant code and evidence.

## Secrets

Do not store credentials in repository configuration, rule files, SARIF, or
runtime evidence. Use environment injection or Vault Agent templates. The public
tree ignores `.env`, rendered secrets, Vault tokens, databases, and generated
analysis artifacts. `.env.example` contains names and placeholders only.

Use independent values for:

- `AUTH_SECRET`
- `ENCRYPTION_SECRET`
- `AEGIFY_UPLOAD_TOKEN`
- OAuth client secrets
- integration tokens

## Retention and deletion

Aegify does not impose a remote retention period. Operators should define one for
databases, object storage, CI artifacts, runtime evidence, logs, and LLM-provider
history. Project deletion and backup handling must follow the operator's policy.

## Multi-tenant deployment

The alpha is self-hosted and does not claim hardened hostile multi-tenancy.
Deploy separate instances or strong infrastructure isolation for mutually
untrusted organizations. Limit network egress, use dedicated identities, encrypt
storage, and apply least-privilege database and object-store policies.

## Reporting a privacy issue

Follow the [security reporting policy](/security/reporting) and use GitHub private vulnerability
reporting. Do not include real credentials, private source, or sensitive request
bodies in a public issue.
