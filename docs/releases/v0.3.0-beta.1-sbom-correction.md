## SBOM correction

The initial release-directory SBOM omitted dependencies. The corrected
`aegify-sbom.cdx.json` inventories the original signed release's `scanner/uv.lock`:
**64 dependency components, the Aegify project root, and 84 dependency edges**,
with package URLs and all locked distribution SHA-256 hashes. Every package,
version, edge and artifact hash is checked against that lockfile before publication.

This is a universal **scanner source-lock inventory**, including platform branches,
the `dev`, `storage-pg` and `storage-s3` extras and their transitive dependencies.
It does not assert that every listed package is installed in a default environment.
It does not inventory the separately built dashboard, containers or build tools.
Installing the wheel can resolve different versions; use the tagged source and
`uv sync --locked` to reproduce the locked environment.

The signed tag, source commit and wheel are unchanged. `SHA256SUMS` now covers
the wheel, corrected SBOM and `sbom-correction.json`. The correction record links
the original asset hashes, lockfile hash, release commit and correction workflow.
The original wheel retains its tag-based release attestation. The replacement
files have **new attestations from the correction workflow on `main`**, rather
than claiming that the initial release workflow produced them.

```bash
sha256sum -c SHA256SUMS
gh attestation verify aegify-sbom.cdx.json --repo Aeg1sx/Aegify \
  --signer-workflow Aeg1sx/Aegify/.github/workflows/repair-beta-sbom.yml \
  --source-ref refs/heads/main --deny-self-hosted-runners
gh attestation verify SHA256SUMS --repo Aeg1sx/Aegify \
  --signer-workflow Aeg1sx/Aegify/.github/workflows/repair-beta-sbom.yml \
  --source-ref refs/heads/main --deny-self-hosted-runners
```

CI and future release workflows now reject empty or incomplete inventories
before attestation and publication.
