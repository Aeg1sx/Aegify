# Aegify v0.3.0-beta.1 — Team self-hosting beta

This first release candidate packages Aegify's scanner, CI integration and
self-hosted team workflow for evaluated internal use. It is a **prerelease**:
detector quality, live AI-provider acceptance and operational service objectives
remain incomplete. It is not a general-availability or commercial-readiness claim.

The repository version is `v0.3.0-beta.1`; the Python distribution uses the
equivalent PEP 440 version `0.3.0b1`. Publication is tracked on
[GitHub Releases](https://github.com/Aeg1sx/Aegify/releases).

## Included

- Eight-language parsing, bounded taint and program/call graphs, repository-qualified
  workspaces, JVM/SCIP/Spring evidence and explicit analysis gaps.
- JSON/SARIF interchange shared by CLI, CI and dashboard, stable finding identity,
  retained triage/history, assignment, due dates, tags and audit records.
- Project authorization and expiring project CI tokens; separate durable source
  scan and AI finding-review workers, cancellation and bounded recovery.
- Retained encrypted AI reviews and source investigations with call receipts,
  content hashes and citations. Human decisions remain authoritative.
- Six CLI agent roles with opt-in bounded source list/search/read tools through
  API, Codex and Claude Code adapters (PR #66).
- Project Rule lab, executable YAML auditing and replayable source-only fixtures.
- Encrypted backup/restore, populated database-upgrade checks and pinned CI/container
  dependencies.

## Evidence and known limits

The feature baseline in PR #66 passed 1,288 Linux scanner tests at 84.51%
coverage plus required CI, CodeQL, container and documentation checks. Release
preparation has its own exact-commit checks; see the linked PR and Actions runs
on the release commit. Test totals are not accuracy measurements.

The latest retained public OWASP Python case/CWE evaluation is TP=214, FP=99,
FN=220, TN=660: precision 68.37%, recall 49.31% over 1,193 scored labels.
Another 37 CWE-501 labels are unscored, so the evaluation still exits `3`.
It is a public synthetic diagnostic corpus, not an independent application
holdout. Blocking-channel precision is 42.86% and recall 4.84% on those labels.
Review findings before using them as an enforcement policy.

The CLI six-role source loop writes its output at completion and cannot recover
per-turn state after a crash. The dashboard's durable finding-review worker is
a separate path; not every role shares that implementation. Offline adapter
contracts do not establish live-provider isolation, quality, prices or billing.

This release supports one internal, single-host team installation. Hosted tenant
isolation, multi-host availability and measured service-level guarantees are
outside its scope. Runtime observations and impact proof remain distinct from
static candidates; AI review does not upgrade evidence or grant execution approval.

Full evidence and remaining work:
[quality assessment](https://github.com/Aeg1sx/Aegify/blob/v0.3.0-beta.1/QUALITY_ASSESSMENT.md).

## Install and verify

Python 3.14+ is required for the scanner. The source checkout requires uv
0.12.18; dashboard development requires Node 26.7+ within major 26 and npm
11.19+ within major 11. Containers pin their own runtimes.

After publication, download and verify the release assets:

```bash
mkdir aegify-v0.3.0-beta.1
cd aegify-v0.3.0-beta.1
gh release download v0.3.0-beta.1 --repo Aeg1sx/Aegify
# macOS: shasum -a 256 -c SHA256SUMS
sha256sum -c SHA256SUMS
gh attestation verify aegify_sast-0.3.0b1-py3-none-any.whl --repo Aeg1sx/Aegify
python3.14 -m venv .venv
.venv/bin/python -m pip install ./aegify_sast-0.3.0b1-py3-none-any.whl
.venv/bin/aegify version
```

The checksum manifest names assets in the download directory. Verify its
attestation as well when checking the entire asset set. A wheel installation
resolves its declared dependencies; use the tagged source and `uv sync --locked`
when you need the repository's exact dependency graph. This release does not
publish a PyPI package or a hosted service.

For the complete dashboard/workers, clone the repository and select the verified
release tag, then follow the authentication, worker and backup guides in that
checkout. Configure secrets and identity admission before starting services.

## Upgrade and rollback

Back up and verify the existing installation first. Stop the dashboard and both
workers, apply the documented migrations, then start matching versions together.
This release includes retained review history, rule-fixture jobs, schema parity
and source-tool continuation migrations. Old workers cannot process new source
review snapshots. Preserve the installation encryption key separately.

Rollback uses a verified pre-upgrade backup and the matching previous checkout.
Do not remove new columns from a populated database or run mixed-version workers.
A successful CI upgrade test does not validate a particular operator's backup.

## Release integrity

Publication requires an annotated tag that GitHub reports as cryptographically
verified. CI checks package/tag version agreement. The release workflow builds
from locked dependencies, audits them and publishes a wheel, CycloneDX SBOM,
SHA-256 checksums and GitHub artifact attestations. It publishes beta tags as
prereleases, without marking them as the latest stable release.

The scanner SBOM is a universal source-lock inventory, including every locked
runtime, optional, development and platform-specific package. It is generated
with `uv export --locked --offline --format cyclonedx1.5 --all-extras --all-groups`
and checked against `scanner/uv.lock` for exact package versions, package URLs,
dependency edges and distribution hashes. It describes the scanner lockfile;
it does not inventory a specific installed environment, the dashboard or containers.

The first publication's empty directory inventory requires the separate
[beta.1 correction procedure](https://github.com/Aeg1sx/Aegify/blob/main/docs/releases/v0.3.0-beta.1-sbom-correction.md). That procedure
retains the signed tag and original wheel and issues new attestations for the
replacement SBOM and checksum manifest.
