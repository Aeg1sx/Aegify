Aegify is an alpha-stage, repository-aware white-box application security
platform. It combines source analysis, compiler indexes, program graphs,
framework models, attack-surface correlation, and policy-controlled runtime
evidence without treating every lexical match as a proven vulnerability.

## What Aegify analyzes

- Python, JavaScript, TypeScript, Java, Kotlin, Go, Rust, and Swift syntax;
- repository-qualified symbols, calls, endpoints, modules, and findings;
- CFG, bounded ICFG, SSA/DFG, data-state, points-to, alias, and taint overlays;
- SCIP symbols, Maven/Gradle providers, JVM classpaths, bytecode, and Spring DI;
- frontend HTTP calls, Gateway routes and rewrites, and backend handlers;
- imported SARIF, Semgrep, Joern, HAR, and OpenTelemetry evidence;
- explicitly approved HTTP, browser, proxy, and JVM verification plans.

<Warning>
  Aegify is alpha software. A candidate is not proof of reachability, a runtime
  observation is not exploit proof, and an unresolved link is not proof that a
  path is unreachable. Review the evidence attached to each result.
</Warning>

## Evidence before severity

Severity describes potential impact. It does not decide the CI gate. Broad
heuristics remain visible as advisory candidates. Only supported semantic
evidence, such as a source-to-sink taint path or a structured database operation
sequence, can create a blocking result.
